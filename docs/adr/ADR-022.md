# ADR-022: Claude Haiku 4.5 as the Voice Responder

**Date:** 2026-10-21
**Status:** Accepted
**Supersedes:** ADR-014

## Context

ADR-014 put the responder, the model that both speaks to the visitor and records their answers through `record_<gate>` (ADR-021), on gpt-4o-mini, and deferred model comparison until V2 was stable. Two things since then made the comparison necessary.

First, gpt-4o-mini invents answers. On live run 2026-08-02_121622 it filled every Project Discovery field from a single trailing line that answered the previous gate's question, and on the 2026-10-19 browser replay it filled all five fields after the visitor had answered two questions (vox-2cl.14). Code completes a gate the moment every field holds a value (ADR-021), so invented values completed the gate and were stored as the visitor's.

Second, the prompts said only what not to do. Nothing told the model that each point must come from the visitor, and the "why AI" (link) question read as a question for the model to answer rather than a SPIN need-payoff question the visitor answers.

Richard ran listening calls and headless replays on the salesbot branch `experiment/model-compare` on 2026-10-21 (indexed at `VOX/scratchpad/2026-10-21_salesbot-model-compare/calls/INDEX.md`). Single observations, not rates:

- Claude Haiku 4.5, golden script with speech, before the prompt changes: both gates completed, neither early, answers recorded as they arrived; it filled the link field itself. Median time to first output 654 ms.
- gpt-4.1, same script: asked two questions in a row twice (vox-2cl.15), never got the link answered, ended the call with Project Discovery incomplete. Median 803 ms. Rejected.
- Claude Haiku 4.5 headless, after the prompt changes: asked the new "why AI" question, recorded nothing rather than inventing when the scripted reply did not answer it; every stored value traced to the visitor.
- Reproduction script headless, one run each: gpt-4o-mini reproduced the bug (median 1,008 ms); Haiku did not (616 ms).
- Claude Haiku 4.5, browser replay with speech, after both prompt commits: both gates completed, the link question asked and answered in Richard's words, one summary at the close. Median 763 ms.

## Decision

The responder runs on **Claude Haiku 4.5** (`claude-haiku-4-5-20251001`) through Pipecat's `AnthropicLLMService`, with tool calls run one at a time (`run_in_parallel=False`, as vox-l33 requires). gpt-4o-mini through `OpenAILLMService` stays selectable.

Three settings choose the model, read by `bot.responder_choice` from the environment: `LLM_PROVIDER` (`anthropic`, the default, or `openai`), `ANTHROPIC_MODEL` and `OPENAI_MODEL`. The live service on the Matrix VPS reads its settings from one place, `backend/voice/.env` (its systemd `EnvironmentFile`). A value exported in the shell is overwritten by `.env` wherever the file sets one, because Pipecat's runner reloads `.env` with override, so to try another model locally, set it in `.env`. Nothing preserves a shell-exported choice through that reload: it would serve only local model-swapping during testing.

A missing or blank key for the chosen provider stops the session at assembly with an error naming the key and `LLM_PROVIDER`. There is no fallback to the other provider: a fallback would keep the site answering, silently, on the model this decision retires.

The model change ships with the prompt changes Richard heard (efae108, 6a42260) and with the visitor-reply rule in code (ADR-021, as amended): nothing is recorded for a stage until the visitor has replied in it.

## Consequences

### Positive

- On three replays of the 2026-10-19 reproduction, Haiku never completed Project Discovery and stored no value scored "not said"; it asked for the implication instead of inventing it. gpt-4o-mini, with the same prompts, stored two "not said" values on one reproduction run and completed Project Discovery on the golden script with two (`build/v2/specs/evidence/vox-2cl.14/replay-adjudication-14.md`, `score-14.md`; judgements pending Richard's confirmation).
- Time to first output is lower than gpt-4o-mini's on the same replays: median 611 ms against 1,101 ms over the first reply after each visitor line, 95th percentile 880 ms against 3,345 ms (`score-14.md`).
- The model is one setting away from gpt-4o-mini, so a regression can be compared directly on the same replays.

### Negative

- The protection against invented values is model behaviour and prompts, measured, not enforced. Apart from the visitor-reply rule, nothing in code checks a stored value against the visitor's words; selecting gpt-4o-mini brings the reproduction's fabrication back. Code-checked quotes are deferred as vox-2cl.21, to be built if scored Haiku calls show invented values.
- The live deployment needs `ANTHROPIC_API_KEY` in `backend/voice/.env` on the Matrix VPS before main is deployed, or every live call fails at session start; local development needs it in its own `backend/voice/.env`. If the voice pipeline moves to Pipecat Cloud (ADR-019, vox-9ji.15), its secret set needs the key too.
- Haiku asks more clarifying questions than gpt-4o-mini, so fixed replay scripts can run out before a gate completes; on the golden script the escape backstop's 20-turn budget ended the call before Haiku asked the "why AI" (link) question. On a constructed reply answering all five Project Discovery questions, it stored only what the visitor said but folded the link and experience answers into other fields and asked about the experience again. On the golden script one stored Haiku value is judged "not said": a visitor's "Yep." recorded as confirming a real cost. All of it is in the replay adjudication.
- Two providers' keys and pricing to manage while the evaluator-mode gate judge still calls OpenAI.

### Neutral

- ADR-013 (native tool calling), ADR-020 (pipecat-flows) and ADR-021 (responder-driven recording) are unchanged by the provider switch; the conversation context uses the same provider-neutral message format on both models.
- `GATE_MODE=evaluator` keeps its OpenAI gate judge, which reads `OPENAI_MODEL` directly and is unaffected by `LLM_PROVIDER`.
- The Pipecat 1.x migration (vox-9ji.8) must keep `AnthropicLLMService` working with `run_in_parallel=False`.
