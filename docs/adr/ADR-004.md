# ADR-004: Daily.co for WebRTC Transport

**Date:** 2026-04-05
**Status:** Accepted

## Context

The Voice module needs a WebRTC transport layer to carry real-time audio between the user's browser and the server-side Pipecat pipeline. WebRTC handles the hard problems of real-time media: NAT traversal, codec negotiation, adaptive bitrate, echo cancellation.

Options evaluated:

| Provider | Integration | Room Management | Pricing (low volume) |
|----------|-------------|-----------------|----------------------|
| **Daily.co** | Pipecat first-class transport (`DailyTransport`) | REST API — create/delete rooms programmatically | Free tier: 10K participant-minutes/month |
| **LiveKit** | Pipecat community transport (less mature) | Self-hosted or LiveKit Cloud | Self-hosted: free; Cloud: pay-per-use |
| **Twilio** | No Pipecat transport — requires custom integration | Programmable Video API | Pay-per-use, higher base cost |
| **Agora** | No Pipecat transport — requires custom integration | REST API | Free tier: 10K minutes/month |

Daily.co builds Pipecat. The `DailyTransport` class is a first-party Pipecat processor that handles room joining, audio frame ingestion, and audio frame output. No other transport provider has this level of integration — alternatives require writing custom transport adapters.

The original salesbot used Daily.co, validating room lifecycle management (on-demand creation with short expiration) and the transport's reliability for voice agent sessions.

## Decision

We will use Daily.co as the WebRTC transport provider. The `DailyTransport` Pipecat processor handles room joining, audio input, and audio output as first-class pipeline components. Rooms are created on-demand via the Daily.co REST API (called from the LLM module's room creation endpoint) with short expiration times.

## Consequences

### Positive
- First-class Pipecat integration — `DailyTransport` is built and maintained by the same team
- Room management is simple — REST API for create/delete, no infrastructure to operate
- Free tier (10K participant-minutes/month) is sufficient for V0 through early production
- Prior validation in the original salesbot confirms reliability for voice agent sessions
- Browser-side integration via `daily-js` SDK is well-documented

### Negative
- Vendor dependency — switching transport providers means replacing Pipecat's `DailyTransport` with a custom or community transport adapter
- Daily.co is a hosted service — no self-hosted option, so availability depends on their infrastructure
- Pricing at scale (beyond free tier) is per-participant-minute, which could become significant for long voice sessions

### Neutral
- Daily.co rooms expire automatically — prevents orphaned resources but requires the LLM module to handle room creation on each session
- The frontend connects to Daily.co directly (peer-to-peer WebRTC via TURN/STUN), not through our server — audio never passes through the LLM module
