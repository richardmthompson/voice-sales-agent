# ADR-006: FastAPI for Python Web Framework

**Date:** 2026-04-05
**Status:** Superseded by [ADR-013](ADR-013.md)

## Context

The LLM module needs a Python web framework to expose HTTP endpoints: room creation (`POST /rooms`) and LLM processing (`POST /process`). The Voice module calls `/process` on every conversational turn, so the framework must handle concurrent requests without blocking.

Options evaluated:

| Framework | Async Support | AI Ecosystem | Complexity |
|-----------|--------------|--------------|------------|
| **FastAPI** | Native async (built on Starlette/Uvicorn) | De facto standard for AI/ML APIs | Lightweight — minimal boilerplate |
| **Flask** | Bolt-on async (via Quart or async extensions) | Legacy standard, declining for new AI work | Lightweight but sync-first design |
| **Django** | Added in 3.1+ but not first-class | Rare in AI/ML ecosystem | Heavy — ORM, admin, templates not needed |

The LLM module's endpoints are async by nature — room creation calls the Daily.co API, and LLM processing calls the Anthropic API. Both are I/O-bound operations that benefit from async/await rather than thread-pool concurrency.

FastAPI's automatic OpenAPI schema generation is a secondary benefit — it provides self-documenting API contracts between modules without manual specification maintenance.

## Decision

We will use FastAPI as the Python web framework for the LLM module. FastAPI's native async support aligns with the I/O-bound nature of the endpoints (external API calls to Daily.co, Anthropic). Its lightweight footprint avoids unnecessary abstractions — the LLM module needs routes and request validation, not an ORM or template engine.

## Consequences

### Positive
- Native async — `async def` endpoints with `await` for external API calls, no thread pool overhead
- Automatic request/response validation via Pydantic — catches malformed requests from the Voice module early
- Auto-generated OpenAPI docs at `/docs` — useful for development and debugging inter-module calls
- De facto standard for Python AI/ML APIs — familiar to anyone in the ecosystem, extensive community support

### Negative
- Adds Uvicorn as an ASGI server dependency — one more process to manage in deployment
- FastAPI's dependency injection system adds abstraction that may be unnecessary for V0's two simple endpoints

### Neutral
- Pydantic v2 is required — all request/response models use Pydantic, which is also used by the Anthropic Python SDK
- FastAPI version updates are frequent — pin the version to avoid breaking changes

## Supersession Note

The separate LLM module this ADR assumed was never built. V0 landed with the LLM integrated directly into the Pipecat voice pipeline (ADR-003), and V2 confirmed that tool calling also stays in-pipeline via [Pipecat's native function calling](https://docs.pipecat.ai/pipecat/learn/function-calling) (ADR-013). There are no HTTP endpoints between modules, so no Python web framework is needed. FastAPI may become relevant again if a future version extracts the LLM into a separate service, but that is speculative.
