# ADR-005: Deepgram for Speech-to-Text

**Date:** 2026-04-05
**Status:** Accepted

## Context

The Voice module needs a speech-to-text (STT) service that can transcribe streaming audio in real-time. For a voice agent, STT latency directly impacts perceived response time — every millisecond spent transcribing is a millisecond before the LLM can start generating a response.

Options evaluated:

| Provider | Mode | Latency | Pipecat Integration |
|----------|------|---------|---------------------|
| **Deepgram** | Streaming WebSocket | ~300ms to first partial, ~500ms to final transcript | First-class Pipecat processor (`DeepgramSTTService`) |
| **Whisper (self-hosted)** | Batch (record → transcribe) | Seconds (depends on utterance length + hardware) | Community Pipecat processor |
| **AssemblyAI** | Streaming WebSocket | Comparable to Deepgram | Community Pipecat processor |
| **Google Cloud STT** | Streaming gRPC | ~300-500ms | No Pipecat processor |

Streaming STT is essential — batch transcription (record the full utterance, then transcribe) adds seconds of latency that makes voice conversation feel broken. Deepgram and AssemblyAI both support streaming. Deepgram has a first-class Pipecat processor, while AssemblyAI requires a community integration.

The original salesbot used Deepgram with specific low-latency configuration (`endpointing=250`, `interim_results=True`, `utterance_end_ms=1000`, `vad_events=False`), validated through production testing.

## Decision

We will use Deepgram for speech-to-text. Deepgram's streaming WebSocket API provides real-time transcription with low latency. The `DeepgramSTTService` is a first-class Pipecat processor, handling WebSocket connection management, audio frame forwarding, and transcript frame emission within the pipeline.

The proven low-latency configuration from the original salesbot will be carried forward: `endpointing=250`, `interim_results=True`, `utterance_end_ms=1000`, `vad_events=False` (VAD is handled by Silero, not Deepgram).

## Consequences

### Positive
- Streaming transcription — partials arrive within ~300ms, enabling the LLM to start processing before the utterance is complete
- First-class Pipecat processor reduces integration effort
- Proven configuration carried forward from the original salesbot — no need to tune parameters from scratch
- Deepgram's Nova-2 model is optimised for conversational speech

### Negative
- Hosted service dependency — no self-hosted option, so transcription requires network connectivity to Deepgram's servers
- Per-minute pricing — costs scale with conversation duration (mitigated by short V0 sessions)
- Accuracy varies by accent and noise environment — no way to fine-tune without enterprise tier

### Neutral
- Deepgram's `vad_events` feature is deliberately disabled — Silero VAD (a separate Pipecat processor) handles voice activity detection more reliably, as documented in the Known Gotchas
- Interim results provide streaming UX but the final transcript is what gets sent to the LLM
