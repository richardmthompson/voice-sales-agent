# ADR-018: Resend for Transactional Email

**Date:** 2026-05-26
**Status:** Accepted

## Context

V2 sends a structured summary email to prospects after conversation — discovered opportunities, gate findings, and a book-a-call link. Richard also receives a copy. The email service needs to be simple, reliable, and suitable for low-volume transactional email (single-digit emails per day initially).

Three options were evaluated:

1. **Resend** — Developer-focused transactional email API. Simple REST API, generous free tier (100 emails/day), custom domain support, React Email for templates.
2. **AWS SES** — Enterprise-grade email delivery. Requires IAM configuration, SES identity verification, and AWS infrastructure setup. Overkill for V2 volume.
3. **SMTP via Porkbun** — Direct SMTP from the domain registrar. Fragile, rate-limited, likely to land in spam without proper DKIM/SPF configuration on a shared IP.

## Decision

We will use Resend for all transactional email in V2. Emails are sent as async background tasks via `asyncio.create_task` after conversation end. If Resend fails, the closing screen informs the user honestly and the backend queues a retry with exponential backoff.

## Consequences

### Positive

- Simple integration — single API call with API key auth
- Free tier covers V2 volume with headroom (100 emails/day vs single-digit actual volume)
- Good deliverability out of the box (Resend handles DKIM/SPF for their sending domain)
- Custom domain support available when arlabs.tech sending identity is needed

### Negative

- Third-party dependency for a user-facing feature — Resend downtime means email promises are broken (mitigated by retry queue and transparent error reporting)
- No self-hosted fallback — if Resend is down, emails queue but don't send until recovery

### Neutral

- AWS SES remains the migration path if email volume grows significantly or if SLA guarantees become necessary
- Email content structure (summary, opportunities, CTA link) is independent of the delivery provider — switching providers requires only changing the send function
