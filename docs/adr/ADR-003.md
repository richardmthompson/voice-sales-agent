# ADR-003: Pipecat for Voice Pipeline Framework

**Date:** 2026-04-05
**Status:** Accepted

## Context

The Voice module needs a framework to orchestrate the real-time audio pipeline: receiving audio from the user, detecting speech boundaries (VAD), transcribing speech (STT), routing text to the LLM, synthesising the response (TTS), and sending audio back. This pipeline must run asynchronously with sub-second latency.

Options evaluated:

| Framework | Model | Language | WebRTC Integration |
|-----------|-------|----------|--------------------|
| **Pipecat** (Daily.co) | Processor pipeline — composable frames flowing through ordered processors | Python | First-class Daily.co transport (built by the same company) |
| **LiveKit Agents** | Event-driven agent framework tied to LiveKit infrastructure | Python | LiveKit only (vendor lock-in) |
| **Vocode** | Agent-oriented abstraction over STT/TTS/LLM providers | Python | Twilio, vonage, Daily (via plugin) |
| **Custom pipeline** | Hand-rolled asyncio with provider SDKs | Python | Manual integration with any transport |

The original salesbot used Pipecat successfully, validating its processor model for this exact use case. Pipecat's pipeline ordering (`transport.input → VAD → STT → Processor → TTS → transport.output`) was proven to work with Daily.co, Deepgram, and ElevenLabs.

## Decision

We will use Pipecat as the voice pipeline framework. Pipecat's processor model — where typed frames flow through an ordered chain of processors — maps directly to the audio pipeline's requirements. Each processor handles one concern (transport, VAD, STT, LLM routing, TTS), and the framework manages async frame passing between them.

Pipecat is built by Daily.co, giving first-class integration with Daily.co's WebRTC transport (ADR-004). It is Python-native, aligning with the LLM module's FastAPI stack.

## Consequences

### Positive
- Processor model enforces separation of concerns within the audio pipeline — each processor is independently replaceable
- First-class Daily.co transport integration (same company builds both)
- Python-native — no language boundary between Voice and LLM modules
- Prior validation in the original salesbot reduces integration risk
- Active open-source project with growing ecosystem of processor implementations

### Negative
- Coupled to Pipecat's frame model — switching to a different framework (e.g., LiveKit Agents) would require rewriting the pipeline, not just swapping providers
- Pipecat is relatively young (2024) — smaller community and fewer production references than established frameworks
- Pipeline ordering is strict and not always obvious — incorrect ordering silently breaks audio flow (mitigated by DESIGN.md "Known Gotchas")

### Neutral
- Pipecat's processor model makes provider swaps (e.g., Deepgram → Whisper) straightforward — replace one processor, pipeline continues working
- Framework is open-source (BSD license)
