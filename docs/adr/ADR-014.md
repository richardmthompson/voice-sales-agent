# ADR-014: GPT-4o-mini for Voice Conversation

**Date:** 2026-05-26
**Status:** Superseded by [ADR-022](ADR-022.md) (Claude Haiku 4.5 as the voice responder)

## Context

The salesbot runs an `OpenAILLMService` inline in the Pipecat pipeline. The two-gate system prompt is complex — it encodes the full discovery flow, topic boundaries, and mirror-and-confirm pattern. The model must handle this via prompt engineering alone.

Voice conversation has specific requirements that differ from text-based AI work: low latency to first token is critical for natural turn-taking, responses need to be concise and conversational rather than verbose, and the model must handle structured instruction following within real-time constraints.

GPT-4o-mini is optimised for this use case — fast, conversational, and cost-effective for the high-frequency turn-by-turn calls a voice pipeline generates. GPT-4.1 is available as the code default but is heavier than needed for voice interaction.

V2 adds tool calling (function schemas, structured returns). Switching model provider (Anthropic Claude, Google Gemini) simultaneously with adding tool infrastructure changes two variables at once. If tool calling misbehaves, it becomes unclear whether the issue is the tool implementation or the model's instruction following.

## Decision

We will use GPT-4o-mini via `OpenAILLMService` for V2. It is the best fit for voice conversation — fast time-to-first-token, naturally concise output, and strong instruction following at lower cost. Model comparison testing against other providers is deferred to a separate initiative after V2 is stable.

## Consequences

### Positive

- Optimised for voice — low latency and concise responses suit real-time turn-taking
- Single variable change — V2 adds tool calling on a proven model, isolating infrastructure risk
- Cost-effective for high-frequency LLM calls (every conversational turn)
- Known conversation quality baseline — any regression is attributable to tool integration

### Negative

- Cannot leverage Claude's potentially superior instruction following for complex tool schemas until post-V2
- Locked into OpenAI pricing and availability for V2 duration

### Neutral

- The model switch is an independent initiative — it can happen at any time after V2 without changing the tool infrastructure (Pipecat abstracts the LLM service interface)
- Controlled eval methodology needed for fair model comparison (same conversation scenarios, same tool schemas, measured latency + quality)
